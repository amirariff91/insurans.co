# Hand-off: Edisi redesign, 15 Nov 2026

Start here if you are picking up insurans.co after the Edisi redesign. Read `PRODUCT.md` (the rules) and `DESIGN.md` (the design system) next.

## Terms used

- **Edisi**: the name of the redesign. Every page leads with the answer; on car pages that is the yearly price with an NCD control.
- **NCD**: no-claim discount, the discount a driver earns for each claim-free year (0%, 25%, 30%, 38.33%, 45%, 55%).
- **Answer box**: the module directly under the H1 (`PageAnswer.astro`): a black title bar stating the finding, then any of an optional lead number, one sentence and label/value rows.
- **Dock**: the phone-only bar (`Dock.astro`) that repeats the car, NCD step and price once the answer block has scrolled away.
- **Title bar**: the black bar at the top of a module (`.mod-bar`).
- **Baseline**: a snapshot of live production that site check 1 compares against (`scripts/checks/baseline-4dd50a3.json`).

## How to verify

```sh
bun run build && bun run check && bun run check:site
```

`check:site` fails if any check is skipped (no browser); `bun run check:site:static` runs only checks 1 to 5.

`bun run check` must show 0 errors. `bun run check:site` runs ten checks (details in `docs/checks.md`):

1. **Contract against live**: titles, H1s, descriptions, canonicals, robots, JSON-LD, RM figures and percentages (compared by value, ranges with both ends), phone numbers and ads per page must equal the baseline, except exact allowlisted changes, NCD figures that the data and the site's own helpers predict, and FAQ wording edits that keep the same figures. It also asserts the six NCD steps on every model page and the homepage, plan-page leads and the buy-direct table against the data.
2. **Ads and indexing**: the same pages load AdSense as on live; state pages stay `noindex, follow`; the sitemap matches.
3. **Structure**: one H1, no skipped headings, `lang="ms"`, image attributes, no broken internal links, FAQ JSON-LD equal to the visible FAQ.
4. **Copy hygiene**: no template leaks ("TODO", "undefined", "RM —"), no aggregator links outside `/insurans-online/`.
5. **Photo credits**: every car photo has a credit and appears on `/kredit-foto/`.
6. **Layout**: no sideways scroll and no text under 14px at 320, 390 and 1280px.
7. **First screen at 390×844**: the H1 size, the answer box inside the first screen, the model-page buttons; warns on more than three magenta fills.
8. **NCD control**: prices, totals and savings at all six steps equal the data, without JavaScript on the homepage and all 39 model pages, with JavaScript on four pages; the logo dot moves.
9. **Calculators**: 15 fixed cases across the five calculators, the NCD calculator opening state, the engine-size parser, no-JavaScript behaviour.
10. **Console**: no page errors, console errors or failed first-party requests.

## Open decisions for the owner

- **Jazz / City Hatchback**: the premium uses a RM60,000–98,000 market value, which excludes the RS reference sums insured and older Jazz GK values. Label the headline as an estimate for cars valued RM60,000–98,000 only, or establish separate verified ranges for Jazz GK and City Hatchback.
- **Life insurance premium table**: RM80–150 a month (the page's lead) and the term/whole-life table have no linked quotation or calculation. Provide the dated basis beside the table, or remove the prices and the lead.
- **playwright-core in the project**: not added. Adding it as a devDependency changes `bun.lock`; the Docker build would install it (it downloads no browser) and `check:site` would no longer depend on the workstation's copy. A browser binary is still needed (`CHROME_PATH`).
- **Page weight**: inline CSS grew from about 38 KB to 60–86 KB per page (raw; 7 KB to 12–16 KB gzip), on every navigation. Splitting the Edisi CSS into a cached stylesheet, or trimming unused rules, is the lever.
