# Performance and Core Web Vitals, November 2026

Branch `perf/cwv-2026-11`, from `origin/main` at `c6905c4` (what is live). Nothing here is committed, pushed or deployed.

**Policy that ships** (decided by the owner, `src/lib/third-party.ts`):

- `analytics: 'idle'`: GTM (and through it GA4) is requested shortly after DOMContentLoaded, once the browser is idle (≤ 1.5 s).
- `ads: 'eager'`: AdSense stays in the HTML as before while the account is under review.
- **After AdSense approval**, switch `ads` to `'interaction'` (see "Trade-offs").

## How it was measured

- Lighthouse 12, mobile preset (simulated slow 4G and 4x CPU throttling), headless Chromium 1247, on miccy.
- Each build was served by `nginx:alpine` in Docker with the repo's own `nginx.conf`, so gzip and cache headers match production. Before: unmodified `c6905c4` build. After: this branch with the policy above.
- Five pages, three runs each; every figure is the **median of three runs**. Raw JSON is in `~/.cache/claude-tmp/.../scratchpad/perf/<label>/<page>-<n>.json` (final tables: `before-b`, `after-b`); `summarize.py` in the same folder makes these tables.
- **No test traffic to GA4 in the final tables.** Lighthouse ran with `--blocked-url-patterns` for `*google-analytics.com*`, `*googletagmanager.com/g/collect*`, `*google.com/ccm/collect*` and `*doubleclick.net*`. gtm.js and gtag/js still load and run; only the hits fail locally. Before and after were measured the same way.
  - Earlier exploratory runs (the variant columns in the options table) did send GA4 hits with hostname `127.0.0.1`. Filter by hostname if they show up.
- "3P" means third-party: anything not served from 127.0.0.1.
- These numbers are local and are not the live numbers. The owner's live run (performance 39, LCP 8.0 s) included real network latency and a busy machine; locally, the HTML comes from the same host with no latency. The split between first-party and third-party carries over.
  - On localhost, AdSense also does not load its Funding Choices consent message (142 KB live), because 127.0.0.1 is not a registered AdSense site. Live, the third-party share is that much bigger.

### Reading the numbers honestly

- **Won outright:** accessibility 92–96 → **100** on all five pages; CLS 0.035–0.072 → **0.000**; no render-blocking stylesheet; best practices and SEO stay at 100.
- **The performance score is unchanged within noise** (76–81 vs 80–81), and TBT is slightly higher (700–945 vs 697–761 ms). With AdSense eager, the heaviest third-party script still loads during page load, so LCP is not better either (1.8–2.4 s vs 1.7–2.3 s). Moving GTM after DOMContentLoaded mainly shifts its ~0.3 s of work into the window TBT counts. TBT only counts long tasks after first paint, and an eager tag ran partly before first paint.
- **What moves the score is AdSense.** In the exploratory builds, with AdSense deferred to interaction / 3 s (option C) LCP dropped to 1.7–1.8 s on all five pages. Deferring both (option D) scored 99–100, though D's score is mostly a measurement-window effect. The planned switch after approval is C.
- The first-party code is not the bottleneck. Without third parties, every page scores 99–100 with TBT 0.

## How the loader works

`src/components/ThirdPartyScripts.astro` (inline in `<head>`, after the consent defaults):

- `gtm.start` / `event: 'gtm.js'` is pushed inline, first, exactly as in Google's snippet. Anything `track()` pushes before gtm.js arrives stays queued in `window.dataLayer`, and GTM processes it in order (`gtm.init_consent` → `gtm.init` → `gtm.js` → queued events).
- **`idle`:** scheduled from **DOMContentLoaded**, not `load`, then `requestIdleCallback` with a 1.5 s timeout, or `setTimeout` where `requestIdleCallback` is missing. An eager AdSense tag (or any slow subresource) delays `load` by seconds; GA4 no longer waits for it.
- **`interaction`:** first pointer, key, touch, scroll or wheel event (the load runs just after the event), or `fallbackDelayMs` (3 s) after DOMContentLoaded.
- **Prerendered pages** (`document.prerendering`) arm nothing until `prerenderingchange`, so a prerender that is never opened sends nothing.
- **Tab hidden first:** if the tab is hidden before the timer fires, the script is requested at once (best effort for short visits). The listener removes itself once the script has been requested. It is not literally `once: true`, because a background-opened tab's first `visibilitychange` is to *visible* and must not use up the listener.
- **Back/forward cache:** each script is retried on `pageshow` with `persisted` when it was requested but never ran (`!window.google_tag_manager`; for AdSense `!adsbygoogle.loaded`). A failed request doesn't leave a "done" flag behind.
- `eager`: GTM is injected at once (the old snippet's behaviour). AdSense is rendered as the same static `<script async … crossorigin>` tag as before.
- The GTM `<noscript><iframe>` is unchanged.

## Trade-offs the owner must decide

1. **AdSense after approval.** Switch `ads` to `'interaction'` (option C): about 220 KB and most of the main-thread work leave the load path, at no revenue cost worth noting. Ads start on the first scroll or within 3 s, and most slots are below the fold.
2. **GTM `idle` vs `interaction`.** `idle` (shipping) keeps short-visit sessions. `interaction` gives a lab score of about 99, but a visitor who neither scrolls, taps nor hides the tab within 3 s is not counted, and the lab gain is mostly a measurement-window effect.
3. **EEA consent banner timing.** Unchanged while AdSense is eager. With option C, the Funding Choices message appears on first interaction / 3 s.
4. **Inline CSS.** About +7–8 KB gzip per HTML page in exchange for no render-blocking request. Revert with `inlineStylesheets: 'auto'`.

## How to switch

Edit `src/lib/third-party.ts` only:

- Old behaviour exactly: `analytics: 'eager', ads: 'eager'`.
- After AdSense approval: `ads: 'interaction'`.
- Best lab score: `analytics: 'interaction', ads: 'interaction'`.
- Tune the windows with `fallbackDelayMs` and `idleTimeoutMs`.

## Verification

- `bun run build`: 180 pages. `bun run check`: 0 errors, 0 warnings.
- **Analytics: no hit reached GA4.** All tests used a playwright context that answered every request to `google-analytics.com`, `googletagmanager.com/g/…`/`…collect`, `google.com/ccm` and `doubleclick.net` locally with HTTP 204, recording the URL and body (`scratchpad/perf/tools/ga-safe.cjs`). "Delivered" below means GTM/gtag produced the hit and the stub received it. Each run ends with a count of unstubbed google-analytics.com requests: 0 every time.
  - **Slow AdSense does not delay GA4.** adsbygoogle.js was held 5 s (Axia page). DOMContentLoaded at 211 ms → gtm.js requested at 346 ms → `page_view` hit at 1.1 s, while `load` fired at 5.4 s. Under the earlier `load`-based trigger GTM would not have started before 5.4 s.
  - **Events before GTM arrives are delivered.** gtm.js was held 4 s on the NCD calculator, which was used at 1.6 s (`dataLayer` = `gtm.js, ncd_calculate, ncd_calculate, ncd_claim_check`, GTM not loaded). After GTM arrived: `page_view`, then one batch with `en=ncd_calculate ×2, en=ncd_claim_check`. Same events and order as the unmodified build. (`ncd_calculate` fires twice because the test changes two inputs.)
  - **Back/forward cache.** Run with Playwright's `--disable-back-forward-cache` default removed: the Axia page was left while gtm.js was in flight and then restored (`pageshow persisted=true`). GTM ran exactly once (no duplicate gtm.js request) and `page_view` was sent after the restore. The case where the request is *aborted* and retried on restore could not be produced in Chromium (the held request completed while the page was frozen).
  - **Prerender gate.** Real prerendering did not happen in headless Chromium (`activationStart` 0). With `document.prerendering` emulated as true until a synthetic `prerenderingchange` at 3 s, gtm.js was requested only at 3.2 s, then `page_view` at 4.0 s.
  - Consent: hits carry `gcs=G100` (denied) in both the old and the new build; this server's IP appears to fall in the denied-region list. Unchanged by this work.
- **Contrast, site-wide.** A playwright scan of all 182 HTML files at 412 px un-hides `[hidden]` and `.hidden` blocks, then checks every text node's computed colour against its effective background. Before the fixes: 14 failing styles. After: only decorative glyphs remain, plus the red ✗ marks in one guide's comparison table (listed under "not done"). Statically scanned code can't see content built by script, so the generated NCD/coverage result rows were checked by computing their colour pairs.
- **Layout shift with slow fonts** (playwright, 412 px, every font request delayed 600 ms; sum of layout-shift entries): Axia 0.0002, homepage 0.0004, NCD calculator 0.0007, /car-insurance/ 0.006, etiqa-vs-zurich 0.0002 (before: 0.062 / 0.0027 / 0.177 / 0.067 / 0.072). With only Fraunces 600 delayed (no preload now): 0 to 0.0005.
- **Pages look the same.** Full-page screenshots at 390 and 1280 px, before vs final build, for Axia and the homepage (`scratchpad/perf/shots2/`). Page heights are identical. Pixel diffs (≤ 0.017%) are only the intended contrast changes: footer text and the homepage "NCD 55%" subtitles. No console errors.

## What was not done

- Decorative glyph contrast was not changed: breadcrumb "›" separators, "·" separators, the "+" FAQ toggles, "~" bullets, the large "1." list numerals on /takaful/. The red ✗ marks (`text-red-400`/`text-red-500`) in the comprehensive-vs-third-party guide table are also unchanged. These are visual markers next to text that carries the meaning; changing them changes the look of those pages. Lighthouse did not flag them on the five audited pages.
- **Fonts were already self-hosted** at `c6905c4`. The fonts.googleapis.com / fonts.gstatic.com requests in the live report come from the Funding Choices consent message.
- **Partytown**, **manual ad units**, and a **hand-written fallback GA4 beacon** (`performance/full-session-analytics`) were left out; see the options table. Hand-writing GA4 hits is fragile and can double-count.
- **Batching events** (`performance/batch-analytics-events`) doesn't apply: gtag already batches.
- **`share-web-fonts-across-origins`** is a blocked draft, and the fonts are self-hosted anyway.
- `dom-size` on `/car-insurance/` (822 elements, a warning): it's the full model list, which is the content.
- `content-visibility` (`defer-rendering-heavy-content`): small pages, so the guide's own "don't apply on small pages" rule applies.
- No live-site measurement, no change to GTM, GA4, AdSense or Search Console.
